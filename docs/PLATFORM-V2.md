# 启明星平台重建与运行说明

本次以《启明星AI平台技术开发方案.md》为准，保留原有账户、项目、图片、积分和本地管理凭据。现金收费、订阅与自动续费继续暂停。

## 现状调整

| 原有实现 | 当前实现 |
|---|---|
| 效果图工作台主要运行模拟生成 | 独立处理服务调用已配置图像模型，模拟版本仅保留查看 |
| 材质工具嵌入旧页面、操作弹窗较多 | 工作台原生三栏：清单、原图及预览、模型及参数 |
| 分区识别与取样缺少统一流程 | 全图先分析，再执行 2 行 × 3 列六区识别；所有来源区域保留，不设候选数量上限 |
| 耗时模型请求在网站接口中执行 | 网站只提交和查询任务；独立 Node 处理程序执行模型请求 |
| 材质主要保存在浏览器 | 新材质候选、任务、Diffuse 版本保存到私有云端 |
| 社区嵌入旧页面 | 原生案例浏览、搜索、收藏、发布及作者下载授权 |

## 操作流程

1. 项目中上传原图，或在效果图工作台选择模型、输入提示词和参考图后生成。
2. 切换「材质提取」，提交全图分析和六区识别。共七步，分别计入实际识别用量。
3. 选择材质清单项，核对名称、类别、部位与四角；混合材质、窗户和遮挡区域必须修正。可合并或拆分候选。
4. 确认纯净取样后，逐项或批量提交 Diffuse 生成。每项独立任务，失败需用户明确重试。
5. 对照原区域、Diffuse 和 3×3 平铺检查结果，填写实际物理尺寸并确认视觉效果，再入库。
6. 导出材质清单与已确认的 PNG。所有通道只启用 Diffuse。

项目可重命名、归档和恢复，封面采用最近保存的效果图。已确认的材质版本不可直接覆盖。

## 处理服务

在本机应用目录运行 `npm run worker`。Windows 使用当前用户的 DPAPI 加密保存专用处理凭据和模型解密私钥；不得提交 `.env.worker.local`、`.env.local` 或 `.local/` 到 GitHub。

处理程序不训练本地模型，仅编排供应商 API。它只处理用户主动排队的任务。电脑关机、网络断开或程序停止时，排队任务仍保留。处理中任务十五分钟无心跳会标记失败；可能已产生用量，因此不自动重试。

当前默认图像模型沿用千问配置。识别、效果图和 Diffuse 三个用途可在本地管理中心分别配置。可用协议仅限国内通道（阿里百炼、火山方舟，以及接入 DeepSeek、智谱、硅基流动等国内厂商的兼容接口）；图像生成需选择支持图像输出的模型连接。新增连接仍由管理员在管理中心填写密钥。

## 数据和权限

Supabase 新表启用 RLS，浏览器只能读取所属工作空间数据；任务创建、编辑和确认通过校验事务完成。处理程序凭据仅允许读取处理中任务涉及的原图、蒙版与参考图，以及写入该任务指定结果路径。

首页只查询主动发布案例的封面及说明。私有原图、项目、材质 ZIP 不进入首页；材质交易仍需作者同意。

部署迁移顺序：`platform-v2.sql` → `platform-v2-integrity.sql` → `platform-v2-catalog.sql` → `platform-v2-worker-recovery.sql`。首次部署前须生成专用处理凭据并登记其摘要；SQL 中的摘要对应本次授权电脑，不能拿来配置另一台电脑。

## 验证边界

已验证编译、类型、接口适配、区域坐标与证据合并；数据库事务测试验证先全图后六区，无测试数据留存。此次未调用收费模型，不能据此宣称实际识别或贴图质量已验收。

历史浏览器材质项目保留原入口供查看、手动处理与导出，尚未自动迁移到新云端材质库。旧的同步 AI 入口已关闭，新的 AI 请求统一走工作台队列。

Diffuse 是效果图的视觉近似，不是原始三维场景真实烘焙。FBX、模型处理和报建检测不在本期范围。
